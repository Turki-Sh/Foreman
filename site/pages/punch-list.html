How it works.

It audits what it saw, never what it assumes, and it tells you what it could not check.

  1. It looks at the real thing. A URL at 1280 and 375 wide, the source, every control clicked, and a URL that does not exist. A local project is run, and its built CSS read. A screenshot gets audited for what is visible, and the rest is listed as unchecked.

  2. Broken first. Dead buttons, links to #, a nav that vanishes on a phone, missing focus states, contrast under 4.5:1, a 404 that returns 200.

  3. Then unfinished. The head block, the share card, the favicon, the sitemap, and every number on the page that has gone stale.

  4. Then generated. Every tell from Foreman's list that it can see, including ones that might be a deliberate style. You strike the ones you chose, once, and it never raises them again.

  5. Then notes against the standards. Type scale, line length, spacing, motion timing. Notes, not defects, because a standard is a default you are allowed to leave.

  6. Then fixes, one at a time. If it can edit the project, broken first, each fix shown. If not, the list goes to whoever builds it.

No score.

The list has counts and no grade. A number nobody measured is the same as a statistic nobody measured, and Foreman does not invent those. Three broken items you can fix today say more than "72 out of 100".

In a Foreman session the punch list is step 6: nothing ships until the broken group is empty. Run before the build, it goes into the brief as fixes instead.
